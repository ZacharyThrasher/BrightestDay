# MoveOp registry (claim before you build — see BRIEF.md §5)

Existing ops (crates/bd_sim/src/powers/data.rs `enum MoveOp`): Cast, Impulse, Blink, Reel, Shove, Field,
Room, Swap, Portal, Link, Explode, Carve, TimeStop, Restore, Transform, SelfStatus, Weigh, SlamOnLand.

Format: `- OpName — one-sentence behaviour — owner worker — status (claimed / building / done)`


## How to register a generic op (the hub is `crates/bd_sim/src/powers/ops/mod.rs` — CONTENT: ARENA GAMES set it up, 01:40)
Already wired (don't add more hooks for these): `run_op`'s last arm forwards EVERY unknown MoveOp to
`World::run_generic_op` (ops/mod.rs); `step_powers` calls `World::step_generic_ops(dt)` first thing
(runs even when nobody holds a power — borrowed moves); `powers_on_hit` calls `World::ops_on_hit`
first (before any held-power rule); `PowerWorld::ops: OpState` (cleared with the round);
`PowerEvent::Op(OpEvent)` carries presentation moments; `World::fire_op(player, &op)` runs one op
directly (tests / tools); `ops::active_secs(op)` + `World::op_busy(player)` are for chains.
To add yours, under `target\locks\powers_ops.lock`, touch only ops/mod.rs (+ data.rs for the variant):
1. `mod your_op;` in the list; 2. a field in `OpState` (fixed array `[Option<T>; MAX_PLAYERS]` indexed
by player index, validated by owner id) + its `any_active()` line; 3. an arm in `run_generic_op`;
4. a `self.step_your_op(dt)` line in `step_generic_ops`; 5. OpEvent variant(s) for presentation;
6. an `active_secs` arm if it has a duration. Helpers there: `op_eye_look`, `op_at_point`,
`op_aimed_player(i, range, cone)`, `op_touch`, `op_event`, `flat`.
bd_game `power_hud/labels.rs::move_verb` has a wildcard arm now (add a verb arm if you care).
